# QA and Regression

1. Transforme cada critério de aceitação em um ou mais cenários verificáveis.
2. Descubra scripts reais no package manifest, Makefile, README, CI e ferramentas do projeto.
3. Cubra happy path, validação, permissões, falhas, estados, limites e regressões.
4. Execute testes unitários, integração, E2E, lint/typecheck/build conforme aplicável.
5. Registre comando, ambiente, resultado, contagem e logs resumidos sem dados sensíveis.
6. Não edite implementação, testes ou snapshots.
7. Retorne PASS/FAIL/BLOCKED; testes não executados são NOT RUN, não PASS.
